# 黑纱下一轮实验与落地执行方案

日期：2026-10-28。此文接替 10 月 26 日的初版方案，依据 10 月 27 日已完成的六相机失败分类、源图盘点、M4 权重复现和人手门控核算制定。目标是回答：**在真实时间顺序、相同 DINO 特征和参考池下，人工标注训练的 M4 预测头能否比现役 M0 多检出且定位正确的黑纱，同时不增加正常误报和拒判？**

## 1. 已知事实与本轮边界

- 七月开发批去重后 69 帧，16 张缺陷均来自同一次故障；F2 为 69 张锁定批，缺陷真值尚空。两批 138 个 SHA-256 不交叉。七月缺陷出现前有足够历史正常参考的数量为 **0/16**，F2 按同状态事件分组的就绪帧为 **0/69**。本地检索未找到额外七月原始连续帧。旧六折结果只能说明开发批内机制，不能回答新故障召回。
- 原 M4 六折可由冻结缓存和权重复现：69 帧框与点命中完全相同，分数最大 CPU/CUDA 差约 `1e-4`。这证明加载与前处理可复现，尚未证明旧权重适应因果历史参考。
- 六相机旧结果显示：M4 在 Cam2 补回 M0 的两张低分缺陷；Cam3 两张定位对却没越阈；Cam4/Cam5/Cam6 的正常高分与缺陷分数重叠。只调阈值无法修好所有相机。Cam3 `10-11-55-177` 的正常标签有历史疑点，必须保留敏感性分析。
- 人手门控的旧分数事后核算让 M0/M4 各少 3 张正常误报，但 8 张拒判里有 1 张同时含真实缺陷。不能把删帧后的误报下降称为在线模型收益。
- **生产口径以 C# 为准。** `csharp/BlackYarnDetector.cs` 每相机缓冲 **8 帧**，第 9 张才评分，首 8 帧作留一分数校准，阈值为中位数加 `3.5×MAD`；人手和第一恢复帧跳过，其余帧包括报警帧都入池。`src/deploy_black_detector.py` 默认 `DET_BUF=16`，所以不能不加配置就把 Python 离线结果当 C# 产线复现。C# 无手帧入池的现状也意味着参考会被漏报的缺陷污染，这必须在真实回放中计入。

本轮**不重训旧 M0**，不在七月 16 张阳性上继续选择 YOLO/新头/阈值，不用 F2 标注或输出调模型。F2 即使盲法完成标注，在找到其故障前同状态参考之前也不能做当前 DINO 协议的因果召回测试。

## 2. 固定实验臂与可回答的问题

| 臂 | 模型与阈值 | 参考/门控 | 目的与就绪时间 |
|---|---|---|---|
| P0：现役基线 | C# M0，首 8 帧留一 `median+3.5×MAD`，阈值随后固定 | 8 帧滚动缓冲；现役人手及第一恢复帧跳过；其余帧均入池 | 忠实量出现役产线状态，第 9 张可判 |
| P1：只改校准 | 与 P0 相同的 DINO 特征、异常图和定位规则；另外以前段 **100 张已确认正常**帧的图分数取 P95 | 同 P0 的参考与门控 | P0 对 P1 看相机内校准是否降低误报；校准完成后才可判，需报告新增预热代价 |
| P2：监督头影子 | 固定六个既有 M4 折权重，**等权平均六张 patch 概率图**后取最高 1% 均值；每折沿用自身训练均值/标准差；以前段同一批 100 张正常帧的图分数取 P95 | 与 P1 **同一 DINO 特征、8 帧历史参考和人手门控** | P1 对 P2 在同一可判帧上看预测头的净收益；只记影子日志，不触发 PLC |

P1/P2 的 P95 固定为 `numpy.quantile(scores, 0.95, method="linear")`；校准图不得进入盲测指标。P2 的六折等权方案在看新流输出之前固定，不根据七月或新流挑单个最好折。M4 的输入仍是 `[F,R,|F−R|,1−cos(F,R)]` 共 193 通道；每个 patch 的 `R` 从**过去**同相机 8 帧中选最高余弦相似者。先使用现有权重作迁移影子实验；它们来自回顾性参考训练，分数漂移本身是待检现象。P2 不是统一可部署新模型，通过独立事件验证后才考虑统一模型训练。

P0 与 P1 的差别包含阈值校准所需的额外时间，不能只比较共同可判帧而隐去 P1 的 `NOT_READY`。P1 与 P2 在同一可判集合比较，才能隔离监督预测头贡献。历史 LAB 外观掩膜曾改善定位却未修好手部误报，**不列为本轮主臂**；若另做，标明诊断实验并单独冻结参数。

## 3. 连续执行任务、产物与通过条件

### T0　标签与数据封存（可立即做；不等新缺陷）

1. 保持七月为 `development_single_fault`、F2 为 `locked_blind_holdout`。现有 `data/black_next_stage_manifest_2026-10-27.csv` 和 `data/black_shadow_asset_freeze_2026-10-27.json` 是初始哈希基准；新增数据按 `data/black_stream_manifest_template.csv` 逐帧记录 SHA、机位、毫秒时间、状态 ID、速度、采集会话 ID、文件路径与预先划好的分区。`partition` 只允许 `warmup`、`normal_calibration`、`blind_stream`；盲测的 `operator_confirmed_normal` 必须留空。独立真值另写 `data/black_blind_labels_template.csv`，模型运行前不得读取。未知状态必须空值，不能用文件名推断为“正常运行”。
2. Cam3 疑似漏标帧由两名看**原图且不看模型输出**的人独立判读；分歧复核后签字。若仍不确定，将它单列并分别按正常/缺陷给出敏感性结果，不能静默改写原 JSON。已备六相机同一时刻的无预测框对照图。
3. F2 的 69 张使用现有 `data/f2_blind_review_69_template.csv` 盲判有无缺陷、位置/框、不可判原因；至少双人独立，锁定审定文件及哈希后才看模型输出。即便没有 F2 阳性，也可准备正常图审计，但不能把没有合格参考的 F2 误报率当产线口径。

**通过：**去重、分区、标签来源和哈希可复算；F2 不进入训练、阈值或模型选择；疑似标签有明确的“待定”状态。

### T1　补齐可用的正常历史（当前真正的数据门槛）

优先从现场上位机、录像或数据库导出六机位**连续原图**，记录生产速度、启停、换布、手部检测结果和采集间隔；每次状态切换生成新的 `state_id` 并重置参考。若本地没有七月故障前记录，就从下一次正常运行开始保存，不需要等待再次出现黑纱。图像不得裁剪或重编码后冒充原始帧。

每相机每状态按时间事先划分：前 **8 张操作员确认正常、无人手的帧**作 P0 预热；后续目标 **100 张确认正常帧**作 P1/P2 阈值校准；再后至少 **100 张盲测正常帧**并保留连续运行时长。100 张只是可开始试验的工程目标，时间相邻图高度相关，正式 FPR 置信区间不足时继续延长观测，不能把 100 张说成 100 次独立事件。校准期间若发现缺陷或手部入侵，该帧剔出校准并保留事件记录，不从盲测中事后挑图。

**通过：**每条待测帧的过去 8 张参考可列 ID；无未来帧、异机位或异状态参考；预热与校准均在盲测之前。现有七月/F2 均不满足，不能靠回填故障后图片解锁。若现场当前无法采集，T2 软件准备继续，P0–P2 的因果准确率项保持“未就绪”。

### T2　实现只读影子回放（可先用合成时间序列验收）

1. 增加流清单校验器：拒绝缺失/重复 SHA、无相机或时间、状态逆序、分区交叉、同图跨开发/F2、盲测标签流入校准。保存 `manifest.json` 的哈希和规则版本。
2. 把 `tools/m4_causal_shadow.py` 的输入守卫接入实际时间流。当前原型要求每张参考 `confirmed_normal=True`，只适于已确认的校准段；正式盲测**不能用事后真值决定参考帧能否入池**。要把“操作员确认的预热帧”和“按 P0 预先固定的无人手入池规则”分开记元数据，P0/P1/P2 共用同一缓冲。否则得到的是使用测试标签的理想参考池，不是部署实验。
3. 对每张图只提取一次 DINOv2 特征，P0/P1/P2 共用。影子日志逐帧写：图 SHA、时间、相机/状态、门控状态、参考 ID 列表、阈值版本、三臂分数/框/报警、耗时、CPU/GPU 后端和是否入池。日志即使 `NOT_READY` 或手部拒判也要有记录；不得触发生产报警、PLC 或改变 M0 路由。
4. 同图比对 C# P0 与 Python P0：先用固定小序列核对门控、参考数、图分数、阈值和框，再做六路长序列。Python 必须显式设 8 帧缓冲、默认无 LAB 掩膜、报警帧继续入池；若 ONNX 与 timm 特征存在数值差异，记录分数/框差值，不能把不等价的两条路径当“只换了头”。

**通过：**未来/异状态/手部帧入池的负例断言通过，重复回放逐帧一致，C# 与 Python 的 P0 状态及报警一致或每个差异有原始日志解释。P2 可在无真标签的正常时间流上只读运行。现有 `m4_causal_shadow.py smoke-causal`、`verify-archive` 是前两项已完成的基础校验；实际流回放脚本与清单校验器尚需实现。

**资源约束：**3200 像素宽时一张 32×228×6144 的 float32 特征约 171 MiB；六相机各 8 张缓冲约 8 GiB。P0/P1/P2 必须共享特征和参考缓冲，不能各复制一套 DINO。报告六路峰值内存、推理延迟 p50/p95、积压/丢帧和实际 GPU/CPU 后端；如六路长期积压，先优化工程再评价精度。

### T3　先测正常误报，再等独立故障（T1/T2 通过后执行）

正常盲测段先冻结规则、阈值与模型哈希，再一次性回放，分机位/状态报告 P0/P1/P2 的正常误报数与 FPR、Wilson 95% 区间；有连续采样时长才算 FP/小时。记录 `NOT_READY/HAND_INTRUSION/RECOVERING` 各自帧数与时长。主比较 P1 对 P2 采用**同一可判帧配对**；同时给出整段全流统计，防止靠多拒判降低误报。生产规格的正常 FPR 上限为 **5%**；点估计满足但置信区间过宽时只记“试运行可接受、证据不足”，延长正常流，不宣布正式达标。

新故障自然出现时封存故障前至少 8 张正常预热、故障全程、恢复全程及独立人工框；整事件只进一个分组。先以至少 **2 个不同于七月的事件**做迁移预检，仍不足以支持生产替换。正式考虑替换需更多独立事件、各机位正常连续观测，并同时满足：P2 在同一可判帧上的“报警且点命中”多于 P1，缺陷事件漏检不增加，正常误报及拒判覆盖不劣于 P0，且六路时延/内存可承受。若某一条件未满足或独立事件仍太少，保留 M0 生产、M4 继续影子；不得选择事后最有利阈值。

## 4. 每轮必须交付的结果表

| 维度 | 必填结果 |
|---|---|
| 数据 | 相机、运行状态、会话/故障事件数，开发/校准/盲测帧数与哈希；标签待定数 |
| 覆盖 | 预热、正常可判、人手、恢复、其他不可判帧数与占全流比例；有人手且有缺陷的帧单列 |
| 检测 | 各臂 TP/FN/FP/TN，缺陷事件与帧级召回，正常 FPR 和 Wilson 95% 区间；同一可判帧的配对差值 |
| 定位 | 点入人工框、报警且点命中、IoU≥0.1/0.3/0.5；把“报警点错”和“未报警但点对”分开 |
| 运行 | 参考池 ID、阈值来源与冻结哈希、FP/连续小时、p50/p95 时延、六路峰值内存、丢帧、后端 |
| 局限 | 独立故障事件数、运行状态缺失、疑似错标敏感性、模型参考协议与训练协议差异 |

## 5. 从今天起的执行顺序

1. **已完成，无需重做：**七月/F2 哈希清单、六相机失败分解、人手门控事后核算、M4 六折权重与 193 通道复现、资产冻结。
2. **先做软件准备：**流清单校验器、P0 与 C# 同口径回放、共享缓冲的 P1/P2 影子日志、合成序列负例及资源测试；全部只读，不改生产报警。可在没有新黑纱时完成。
3. **并行准备证据：**现场正常流采集与状态记录、Cam3 疑似标签双人复核、F2 无模型输出盲判。若拿不到原始正常历史，记录缺口并保持 P0–P2 因果指标空白。
4. **一旦 T1/T2 通过：**冻结规则和阈值，跑正常流盲测；下一次独立故障到来后再做事件召回。任何新结果先出逐帧报告，再讨论是否值得重训统一 M4 或接入 C#。

本方案不要求短期采到新黑纱才能推进工程和正常误报评估；**证明预测头提高真实黑纱检出**则必须等独立故障与其前置参考，不能由同一次七月故障的更多训练轮次代替。
