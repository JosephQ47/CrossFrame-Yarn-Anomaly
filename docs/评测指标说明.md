# 评测指标说明：工业异常检测论文该报哪些指标

这份文档解释本仓库报的每一个指标是什么、为什么要报、审稿人会怎么看它。
计算代码在 `python/metrics_full.py`，结果在 `data/metrics_黑纱基准.json`。

---

## 一、先分清两件事：检测 vs 定位

工业异常检测（Industrial Anomaly Detection, IAD）论文的指标一律分两层，缺一层会被审稿人问：

| 层次 | 回答的问题 | 英文习惯写法 |
|---|---|---|
| **图级 / 检测** | 这一帧有没有缺陷？ | image-level, I-AUROC |
| **像素级 / 定位** | 缺陷在**哪里**？ | pixel-level, P-AUROC, PRO |

只报图级，审稿人会说"你可能是靠别的线索猜对的，没有证据说明模型真的看到了缺陷"；
只报定位，则没有说明产线上会不会满屏误报。本项目两层都报。

---

## 二、图级指标

### 1. AUROC（必报）
ROC 曲线下面积。取值 50 = 随机，100 = 完美。

**含义**：随机取一张缺陷帧和一张正常帧，模型给缺陷帧打更高分的概率。

**优点**：与阈值无关，所以不同方法可以公平横比——这是 MVTec AD 等基准把它当主指标的原因。
**缺点**：正负样本极不平衡时会偏乐观（负样本多，FPR 分母大，少量误报看起来不严重）。

> 本项目：**98.2**（69 帧 / 16 缺陷）

### 2. AP，也叫 AUPR（推荐必报）
Precision-Recall 曲线下面积（average precision）。

**为什么要额外报它**：缺陷检测天生不平衡（本项目 16 正 / 55 负，真实产线更极端，
可能 1:1000）。AP 直接反映"报警里有多少是真的"，对不平衡比 AUROC 敏感得多。
**近两年 IAD 论文基本都会同时给 AUROC 和 AP**，只给 AUROC 容易被质疑。

### 3. F1-max
遍历所有阈值取到的最好 F1。

**含义**：这个方法在**最理想阈值**下的上限性能。
**注意**：它是**乐观上限**，因为最优阈值是在测试集上选的（等于偷看了答案）。
所以 F1-max 只能用来比较方法潜力，**不能当成部署性能报**。

### 4. 产线定阈下的 精确率 / 召回 / F1（工程论文必报）
阈值只用**纯正常帧**定（本项目取正常帧分数的 P95），完全不看缺陷帧。

**为什么这个才是真实性能**：产线上线时你手里只有正常运行的录像，没有缺陷样本可以调阈值。
一个只有 F1-max 好看、但"用正常样本定不出可用阈值"的方法，工程上是废的
——本项目早期用 max 作图级分数时正是这种情况（μ+2σ 阈值下只有 6% 召回）。

> 本项目：见 `data/metrics_黑纱基准.json` → 图级 → 产线定阈

### 5. FPR@TPR=100%（缺陷不许漏的场景要报）
要求一个缺陷都不漏时，被迫承受多少误报率。

**为什么**：纺织缺陷漏检的代价（整卷布报废）远大于误报（工人多看一眼）。
业务方问的往往就是这一句："一个都不漏的话，我一天要白看多少次？"

### 6. TPR@FPR=5%（误报有预算的场景要报）
反过来：把误报压到 5% 时还能抓住多少缺陷。

**为什么**：产线对误报有硬预算（报警太多工人就不看了，叫 alarm fatigue）。
这两个指标（5、6）是 ROC 曲线上业务方真正关心的两个工作点，比整条 AUROC 更有说服力。

## 三、定位指标

### 7. 点命中率（本项目自定义，需说明口径）
预测的异常连通域**重心**是否落在 GT 框内。命中数 / 缺陷实例数。

**为什么用它**：本项目 GT 是**矩形框**而非像素掩膜，算不了严格的像素级指标；
而"指出的位置对不对"是工人现场唯一在乎的事（报警框套住缺陷，他就能一眼确认）。
**报的时候必须说清这是点级命中而非 IoU**，否则会被当成夸大。

> 本项目：**15/16 = 94%**

### 8. 像素级 AUROC（P-AUROC，IAD 论文标配）
把每个像素当一个样本算 AUROC。

**⚠️ 本项目的口径必须声明**：GT 是框，框内的正常像素被当成了缺陷像素，
所以这个数字**偏保守**（模型只在真缺陷上响应也拿不到满分），
**不能与 MVTec AD 等有精细掩膜的数据集横比**。只用于本项目内部方法比较。

另外统计**只在筘齿带内**做：检测器只在带内输出，带外恒为 0，
若把带外像素计进去会把 AUROC 无意义地推高到接近 100（因为带外全是"正确的负样本"）。
**这是 IAD 论文里最常见的一种指标注水，必须主动避免并说明。**

### 9. PRO（Per-Region Overlap，IAD 论文标配）
对每个缺陷区域单独算覆盖率，再对所有区域**求平均**，最后把曲线在 FPR ≤ 0.3 区间积分并归一化。

**为什么需要它而不只是 P-AUROC**：P-AUROC 按像素平均，**大缺陷会主导指标**——
一个方法只要把最大的那个缺陷圈准，小缺陷全漏也能拿高分。
PRO 先在区域内平均，让每个缺陷不论大小**权重相同**。
本项目缺陷只占全图 0.2%，正是 P-AUROC 最容易失真的场景，所以 PRO 更能说明问题。

### 10. 框 IoU 与框级召回@IoU
预测框与 GT 框的交并比，以及 IoU ≥ 0.1 / 0.3 / 0.5 时的召回。

**为什么阈值取得这么低**：本方法输出的是**异常区域**的外接框，
不是经过框回归训练的检测框，边界天然比 GT 松。
报 IoU≥0.5（目标检测惯例）会低估其实用价值；报 IoU≥0.1/0.3 更贴近"报警框有没有套住缺陷"。
**低阈值必须写明理由**，否则看起来像在挑对自己有利的阈值。

## 四、这类论文还常被要求的东西

| 项 | 本仓库位置 | 说明 |
|---|---|---|
| **消融实验** | `docs/方法说明.md` 第 4 节、`data/sweep_results.csv` | 每个设计单独去掉后的指标变化。审稿人问"你的增益到底来自哪一步" |
| **与已有方法对比** | `data/benchmark_scores.csv`、README 表格 | 至少要有 PatchCore 这类通用 IAD 基线。本项目还包含 6 类改色/域适应方法 |
| **失败案例分析** | `docs/方法说明.md` 第 6 节、`assets/fig3_红纱失败.jpg` | 有失败分析的论文更容易过审。本项目的红纱负结果就是标准素材 |
| **推理耗时 / 显存** | README 部署章节 | 工程类期刊必问。本项目 GPU 单帧 ~0.4s、CPU ~5s、6 路峰值 5.76 GB |
| **置信区间** | 见下 | 小样本必须给 |

### 关于置信区间（本项目的最大软肋）
只有 **16 个缺陷实例**。15/16 的 95% Wilson 区间约为 **[0.72, 0.99]**——
也就是说真实召回可能低到 72%。**1 个样本的翻动就是 6% 的指标变化。**

所以：
- 报"94%"时必须同时给区间，否则属于夸大；
- 在这个样本量下，两个方法差 3~5 个点**没有统计意义**，不能声称谁更好；
- 论文里应把这一点写进 Limitations，而不是等审稿人指出来。

## 五、一句话总结该报什么

> **图级**：AUROC + AP + 产线定阈下的 P/R/F1 + FPR@TPR100%
> **定位**：P-AUROC + PRO（并声明框掩膜近似口径）+ 点命中率
> **配套**：消融、与通用 IAD 基线对比、失败案例、耗时显存、置信区间

## 六、定阈相关指标（§3.6 用到的）

这一节的指标回答的不是"排序好不好"（那是 AUROC 的事），而是**"选定一个阈值之后，实际会误报多少、漏检多少"**。
工程上真正关心的是后者。

### 11. 图级异常分数

本方法的图级分数**不是概率，也不是距离**，而是一个整数：

> 把 patch 级异常图按 P99 二值化，取所有连通域中**面积 ≤ 55 patch** 的那个**最大连通域的面积**（单位：patch 个数）。

- 为什么用面积而不是最大值：缺陷是**空间聚集**的，一团相连的高异常 patch 才是缺陷；
  单个 patch 的极大值容易被噪声顶起来。改用面积后 AUROC 从 81 升到 96.4。
- 为什么设 55 的上限：超过 55 的连通域基本是人手、白纸卡这类大面积入侵物，不是纱线缺陷。加上限后 AUROC 96.4→98.2。
- 取值范围：正常帧典型 2~9，缺陷帧典型 12~49。**它是整数，这一点对下面的保形方法有影响**（并列值多，p 值偏保守）。

### 12. 四条定阈规则

| 规则 | 公式 | 有无误报保证 | 超参 |
|---|---|---|---|
| **MAD**（现行部署） | `thr = 中位数 + 3.5 × max(1.4826·MAD, 1)` | **无** | 3.5 是试出来的 |
| **P95** | `thr = 校准集的 95 分位` | **无** | 无 |
| **保形 p 值** | `p(s) = (1 + #{校准分 ≥ s}) / (n+1)`，`p ≤ α` 报警 | **有**：`P(误报) ≤ α` | α（目标误报率） |
| **极值理论 POT** | 对超过 70 分位的尾部拟合广义帕累托分布，外推到风险 α | **有**（渐近） | α |

- `MAD` = 中位绝对偏差（median absolute deviation），`1.4826` 是让它在正态分布下等价于标准差的换算系数。
  取中位数而非均值，是为了不被少数高分帧带偏。
- **保形（conformal）的保证怎么来的**：只要校准帧与测试帧「可交换」（exchangeable，可粗略理解为同分布且无先后之分），
  那么一个新的正常帧其 p 值小于 α 的概率就 ≤ α。这是分布无关的，不假设分数服从任何形状。
  代价是：n 帧校准的**最小可声明** α = 1/(n+1)——8 帧最多只能声明 11%。
- **POT 为什么更实用**：它不看整个分布，只对尾部（这里取 70 分位以上）拟合广义帕累托分布再外推，
  所以不会像保形那样被**单个**高分帧顶死阈值。代价是外推到远小于数据量的 α 时不可信（本项目 α=1% 已在数据之外）。

### 13. 留一法误报率（LOO FPR）

对每一个正常帧，**把它自己从校准集里剔除**，用其余正常帧定阈，再看它是否被判为报警。
报警的比例就是留一误报率。这样做是为了避免"用自己校准自己"造成的乐观偏差。
缺陷帧的召回则用**全部**正常帧做校准（部署时校准集本就不含缺陷帧）。

### 14. 两种校准范围

| | 含义 | 校准帧数 | 对应的部署形态 |
|---|---|---:|---|
| **按机位** | 每个相机只用自己的正常帧定阈 | ≈8 | 现行部署脚本（每路独立自校准） |
| **合并** | 六个机位的正常帧合到一起定阈 | 52 | 分数是面积计数、跨机位量纲一致，故可合并 |

### 15. 样本量：无分布假设的上容忍界

要以 95% 置信度声明"误报率 ≤ α"，用 n 个正常样本的最大值作阈值时需要 `(1−α)^n ≤ 0.05`，即：

| 声明的误报率 α | 至少需要的正常帧数 |
|---:|---:|
| 1% | 299 |
| 2% | 149 |
| 5% | 59 |
| 10% | 29 |

本基准有 53 帧正常，**距离"能声明 5%"差 6 帧**。这条直接决定产线标定段该录多长。

### 16. 自助置信区间（bootstrap CI）

所有召回与误报率都给了 95% 区间，做法是**按帧有放回重采样 2000 次**，取结果的 2.5 与 97.5 分位。
16 个缺陷下区间很宽（半宽常达 ±0.15），**两个方法相差几个点没有统计意义**，看区间是否重叠比看均值更重要。
