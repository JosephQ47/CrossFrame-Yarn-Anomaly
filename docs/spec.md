# CrossFrame Yarn Anomaly 需求规格

> 平台：Python 离线/部署验证；.NET Framework 4.7.2 + OpenCvSharp + ONNX Runtime 产线实现  
> 输入：固定机位工业相机图像 ｜ 日期：2026-09-28 ｜ 版本：v0.1（已批准基线）

本文是总规格入口。算法原理和实验边界详见 [`方法说明.md`](方法说明.md)，产线集成和回滚要求详见 [`现场部署手册.md`](现场部署手册.md)。

## 0. 一句话定位

使用固定机位跨帧同位置 DINOv2 特征检测黑纱/深色纱异常，并复用产线既有人手检测结果，避免把人手遮挡误报为纱线缺陷。

## 1. 系统架构

```text
相机帧 ──> 现役人手检测 ── handIntrusion ─┐
                                         ├─> 人手门控状态机 ─> 黑纱异常检测 ─> 状态/分数/框
相机帧 ──────────────────────────────────┘
```

人手检测由现役系统负责，本仓库只消费每相机、每帧的布尔结果。人手门控在 DINOv2 特征提取和参考池更新之前执行。

## 2. 运行环境与资源

| 资源 | 规格 |
|---|---|
| Python 验证 | PyTorch/timm/OpenCV；CPU 或 CUDA |
| C# 产线 | .NET Framework 4.7.2、OpenCvSharp、ONNX Runtime |
| 特征模型 | DINOv2 ViT-B/14，最后 8 层拼接，6144 维 |
| 相机状态 | 每路独立参考池、阈值、人手恢复计数 |

## 3. 检测算法契约

| 项 | 固定值/规则 |
|---|---|
| 检测带 | 图像高度 `0.34–0.60` |
| patch | `14 px` |
| 参考匹配 | 同位置 top-1 余弦相似度 |
| 候选 | 异常分数最高约 1% patch |
| 图级分数 | 面积不超过 55 patch 的最大异常连通域面积 |
| C# 参考池 | 每相机 8 帧 |
| Python 最小参考 | 8 帧 |

## 4. 功能需求

### 4.1 纱线异常检测

无人手且检测器已就绪时，系统计算异常分数和定位框；分数达到相机阈值时输出 `YARN_DEFECT`，否则输出 `NORMAL`。未完成参考池或阈值准备时输出 `NOT_READY`。

### 4.2 人手入侵门控

- 人手状态优先级高于纱线缺陷。
- `handIntrusion=true` 时输出 `HAND_INTRUSION`，不得执行纱线判定，不得产生纱线报警、分数或定位框。
- 人手帧不得进入参考池，不得参与阈值标定。
- LAB 外观屏蔽不是正式人手判据，默认关闭。

### 4.3 恢复状态

- 人手消失后的第一张无人手帧输出 `RECOVERING`，不得判定或入池。
- 连续第二张无人手帧恢复正常处理；若恢复期间再次检测到手，计数清零并返回 `HAND_INTRUSION`。
- 人手出现前的参考池和阈值保留。

### 4.4 参考池完整性

`HAND_INTRUSION` 与 `RECOVERING` 帧绝不进入参考池。正常处理保持原有滚动参考策略；该功能不得改变无人手帧的分数、框、阈值和报警结果。

### 4.5 对外状态与兼容

公开状态集合为 `NOT_READY`、`NORMAL`、`HAND_INTRUSION`、`RECOVERING`、`YARN_DEFECT`。C# 原两参数 `Process(camIdx, frame)` 必须保留并等价于 `handIntrusion=false`；原 `Alarm` 仅在状态为 `YARN_DEFECT` 时为真。

### 4.6 日志和可视化

Python JSONL 每帧记录 `state` 与 `hand_intrusion`。门控帧的 `score`、`threshold` 和 `box` 为 `null`。报警图只在 `YARN_DEFECT` 时生成，并以矩形框展示定位，不使用热力图作为识别结果。

### 4.7 光照泛化边界验证

- 光照鲁棒性必须同时报告正常误报率、缺陷召回、定位命中和图级 AUROC，不得仅以 AUROC 声明可用。
- 合成压力测试至少覆盖全局曝光、Gamma、暖/冷通道偏移、局部阴影、条纹闪烁和局部高光；全局曝光扫描范围为 `-1.5 EV` 至 `+1.5 EV`、步长 `0.25 EV`。
- 必须分别测试：原参考库、只增强正常参考库、参考与查询同条件重新标定三种口径。缺陷帧不得进入参考库。
- “可控安全范围”定义为：正常误报率不超过 `5%`，16 个缺陷最多较原始条件新增 1 个漏检，定位命中不少于 `14/16`。
- 合成结果只用于确定算法敏感边界；最终现场允许范围必须由冻结参数后的早、中、晚真实采集验证。
- 任何实验不得改写 `D:/dataset/black_fabric` 原图和标注。

### 4.8 检测与定位指标契约

- 检测指标至少包含混淆矩阵、正常误报率 FPR、缺陷召回率 Recall、精确率 Precision 和图级 AUROC；FPR、Recall、Precision 同时给出 Wilson 95% 置信区间。
- 定位指标至少包含定位点进入人工框的比例、预测框对人工框的最佳 IoU、中位 IoU、`IoU≥0.1/0.3/0.5` 框级召回，以及“报警且定位点正确”的联合成功率。
- “报警且定位正确”必须同时按缺陷帧分母和全部报警分母报告，防止检测召回与定位命中来自不同帧。
- 每小时误报警次数定义为 `FP / 连续观测小时数`。只有明确提供连续观测时长或固定帧周期时才允许计算；离散抽样图片必须输出不可用原因，不得用首末文件时间跨度代替连续观测时长。
- 评估器必须能从 LabelMe 原始标注回填 GT 框，不得把模型预测结果当作定位真值。

## 5. 软件架构

```text
src/deploy_black_detector.py        Python 因果部署与状态机验证
csharp/BlackYarnDetector.cs         C# 产线检测器与兼容接口
tools/test_hand_gate.py             无模型的确定性状态机回归
src/illumination_stress_eval.py     光照压力测试与参考库增强对照
tools/test_photometric_transforms.py 光度变换确定性回归
tools/evaluate_detection_metrics.py 检测、定位与单位时间误报统一评估
tools/test_detection_metrics.py     指标公式确定性回归
```

现役主程序位于外部工程 `D:\研究生课程\课题\添加按键拍照功能\纱浆检测`：
`MainForm.CameraJPGESPersonProcess` 先写入 `CameraVar.HandIntrusion`，再调用
`CameraJPGESKCProcess`；该 KC 调用点在推理前执行两帧恢复门控。仓库内的 C#
`BlackYarnDetector.Process(camIdx, frame, handIntrusion)` 仍作为独立产线实现接口保留。

## 6. 配置项

| 配置 | 默认 | 说明 |
|---|---:|---|
| `DET_INTRUDER_MASK` | `0` | 实验性 LAB 外观屏蔽，正式人手门控不依赖它 |
| `DET_GATED` | `0` | 原有缺陷报警帧参考池门控 |
| `HAND_CLEAR_FRAMES` | `2` | 人手离开后连续无人手恢复帧数 |

光照压力测试参数属于验证配置，不改变产线默认检测流程；只有通过 §4.7 并经现场复验的策略才可加入生产配置。

## 7. 明确的非目标

- 不在本仓库重复训练或部署人手模型。
- 不在人手遮挡时尝试同时判断被遮挡区域的纱线缺陷。
- 不重复现役系统的人手报警、存图和数据库记录。
